# elihome-listing-writer: change log

Test set: Elihome Classic Silicone Spatula Turner (simple), Classic Series 4-in-1 Cutting Board Set, 4-Pack (complex), Elihome x Peanuts Double-Sided Cutting Board Set, 2 Pack (new). Input: raw specs only (test-products.md).
Each version was run on all 3 products and checked against listing-rules.md with 13 checks per product (title length, brand, 5 bullets, placeholders, symbols, all caps, unproven claims, subjective words, search-term bytes, brands in search terms, MISSING in the attribute table, 5 Q&As, one product-specific check). "What failed" is what the previous version got wrong; "What I changed" is the change that made this version.

| Version | What failed | What I changed |
|---|---|---|
| v1 | Same prompt without the skill: 64% of checks passed. Titles of 168, 174 and 179 characters (limit 75, T1); all-caps bullet headers (B4, B9); no shopper Q&As; missing data not marked; on the Classic set it wrote "heat resistant" with no temperature and didn't flag the two model numbers. | First version: rules file attached; four kinds of statement (fact, derived fact, claim that needs proof, subjective); MISSING only in the attribute table, Q&As and a "To check" list; conflicting specs flagged, not chosen; fixed 8-part output ending with a rule check. Result: 100% of checks passed. |
| v2 | v1 passed every check but the text was weak. Bullets were dry lists of facts: the Classic set's bullet 3 was only "Rectangular boards with a built-in groove" (58 characters). The descriptions repeated the bullets and listed model numbers. | Each bullet pairs a fact with the benefit that follows directly from it, 120 to 200 characters (B7). The description shows the product in use and leaves model numbers and spec lists to the attribute table. Result: 100% of checks passed, clearly better text. |
| v3 | Writing "the product in use" pulled care back in: the Classic set's description ended with "the boards go in the dishwasher", against my decision to keep care only in the attribute table and Q&As (X4). One bullet used the abbreviation "BBQ" (B9). | Care instructions stay out of both bullets and description, even when the specs state them, because Amazon shows the care field on the page. Abbreviations written out ("barbecue", not "BBQ"). Result: 100% of checks passed; no care in any bullet or description, "barbecue" written out. |
| v4 | AI shopper test (new Claude chat, v3 Classic set listing, "I need a cutting board set under $150"). It read "Item dimensions 19 x 14 in" as one board and guessed the set was stacked; it called out the "keep raw meat on one board" pitch because all four boards are the same color; it filled missing facts (board thickness, heat limit, certification, Made in USA) from another Elihome store page, which also shows a third model number (ES-4IN1CS). Its list of missing information matched the skill's "To check" list (XL size, thickness, reversible, heat limit, food safety, warranty terms). | A benefit must not suggest a feature the product lacks (no food separation without color coding). For a set, give each piece's own size and keep any dimension whose meaning is unclear out of customer text. The "To check" list now ends with a reminder to check the same facts on Elihome's other channels, because AI assistants fill gaps from them (AI5). |
